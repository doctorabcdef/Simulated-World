# 重建依据与尺寸校准

当前场景以用户提供的一张房屋右前上方照片为依据。照片可以约束可见外观和相对比例，但无法单独确定真实尺寸、遮挡区域或完整空间布局。代码中的米制尺寸均为估计，当前不具备测量级 1:1 精度。

## 照片可见依据

| 部分 | 当前实现依据 |
| --- | --- |
| 二楼正面 | 白色墙面、左侧窄窗、偏左双开门、右侧宽窗、门边红春联 |
| 二楼右侧 | 靠近前转角的单门、圆形壁挂、后部窗户和通道杂物 |
| 阳台与楼梯 | 正面和右侧连通的平台、银色细杆栏杆、球形柱帽、右前方外楼梯 |
| 阁楼与屋顶 | 后退的灰水泥墙、三组不同宽度的窗、双坡蓝灰瓦顶和白色宽檐 |
| 生活物件 | 两块靠墙门板、木料、扫把、袋子、红砖矮墙、洗衣机、盆栽 |
| 周围环境 | 混凝土院落、贴近房屋的浓密植被、竹木、坡地和远山 |

`src/house.js` 中的 `patches` 记录门窗和靠板在照片上的四角位置。`quadMap()` 与 `photoPlane()` 将这些区域映射到三维平面，门框、窗框、墙体、栏杆和瓦片仍由独立几何构件生成。源图中的固定反射与光照会保留在纹理里，因此近距离或不同角度下仍可能出现与真实材质不一致的地方。

完整图片保存为 `public/reference-house.png`，随网页部署并由站点本地加载。环境中的院落、树叶等纹理由 `src/environment.js` 在运行时生成。

## 推测与补全范围

- 房屋背面、室内分隔与家具、照片外的一楼空间没有充分影像依据。
- 房屋宽深、层高、门窗和楼梯尺寸未经过现场测量。
- 山体、地面坡度、树木的位置和种类根据画面观感补全，未使用地形测绘数据。
- 参考观察视角按照片构图近似设置，未使用原相机参数进行标定。

## 当前尺度与代码入口

| 项目 | 当前估计 | 调整入口 |
| --- | --- | --- |
| 主楼 | 宽约 12.6 m、深约 6.6 m | `src/house.js` 的 `HOUSE`、墙体与楼板构建 |
| 二楼标高 | 3.3 m | `src/house.js` 与 `src/physics.js` |
| 正面位置 | 主墙 `z=1.55`，阳台外缘 `z=3.15` | `src/house.js` 的墙体、楼板、栏杆 |
| 外楼梯 | 22 级，平面长度约 8 m；上端 `z=3.15`，下端 `z=11.15` | `src/house.js` 的台阶/栏杆与 `src/physics.js` 的 `floorAt()` |
| 门窗位置与尺寸 | 按可见相对比例估计 | `src/house.js` 的 `frontWall()`、`window()`、`makeDoor()` 调用 |
| 照片裁取区域 | 使用参考图上的四角坐标 | `src/house.js` 的 `patches` 与 `photoPlane()` |
| 场地和植被 | 根据照片补全 | `src/environment.js` |
| 参考观察视角 | 从房屋右前上方观察 | `src/main.js` 的未进入场景时相机设置 |

尺寸目前分布在建模调用和碰撞逻辑中，修改 `HOUSE` 对象本身不会自动缩放整栋房屋。应用实测尺寸时，应同步修改几何、碰撞体、楼层高度和楼梯判定，避免出现可见台阶与实际行走高度不一致。

## 后续校准顺序

1. 以房屋正面宽度、深度、各层标高建立真实尺度。
2. 测量门窗宽高和离墙角的距离、阳台进深、楼梯总高/总长及级数。
3. 用正面、左右侧、背面与楼梯照片校正遮挡区域，再按平面草图调整室内。
4. 同步修改碰撞和 `floorAt()`，运行 `npm test` 与 `npm run build`，实际检查进门、上楼和阳台转角。
5. 在电脑及目标手机浏览器检查近距离细节和流畅度。

开始画面提供固定的照片参考观察视角。探索期间可通过暂停/帮助菜单的 **返回照片参考视角** 回到该观察位置，便于比较外观；该操作保留本次页面会话的门和物品状态。
